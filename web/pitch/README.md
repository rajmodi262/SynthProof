# The pitch deck

Ten slides for a review panel. Standalone — it does not touch the console, does not need the
FastAPI service running, and makes **no network request of any kind** once loaded. Fonts are
bundled, every number is baked in at build time. It runs on a laptop with the wifi off.

## Run it

From `web/`:

```bash
npx vite --config pitch/vite.config.ts
```

Opens on <http://localhost:5174>. To build a static copy (lands in `synthproof/api/pitch/`,
its own folder so it cannot collide with the console's build):

```bash
npx vite build --config pitch/vite.config.ts
```

## Presenting

| key | does |
|---|---|
| `→` `space` `PageDown` | next slide |
| `←` `PageUp` | previous |
| `1`–`9`, `0` | jump to slide 1–10 |
| `Esc` | overview grid, click to jump |
| `N` | speaker notes — what to say, the source path for every number, and the question the panel will ask |
| `Home` / `End` | first / last |

Tested at **1280×720**. Body copy stays at or above 24px; the palette is high-contrast on a
near-black ground so a washed-out projector still reads. `prefers-reduced-motion` is honoured
throughout, and nothing on any slide is 3D or WebGL.

## Where the numbers come from

Nothing in the deck is typed from memory. `data.ts` is **generated**:

```bash
python web/pitch/build_data.py
```

It reads only the committed `results/*.json` files and writes `data.ts` with a `source` field
on every block. Re-run it after any experiment re-run. If a panellist questions a number, the
speaker notes for that slide name the file to open.

Two things on screen carry an explicit **illustrative** flag, because they are drawn rather
than measured:

- the scatter clouds on slide 5 — the correlation each cloud is drawn to is measured, the
  individual dots are generated for display;
- both tables in the guessing game on slide 3 — rows in the shape of UCI Adult, written for
  the slide. Printing real rows from a real dataset in a pitch deck would be a small version
  of the failure this project is about.

Everything else — every bar, table, readout and interval — is a committed measurement.

The ledger widget on slide 8 computes **real SHA-256** in the browser over the same field
order the Python ledger uses, so the cascade after a tamper is a genuine chain failure rather
than a colour change. The ceiling calculator on slide 6 is a direct transcription of
`synthproof/audit/steinke.py`, checked against `data.ts:ceilingCurve`, which is generated by
running that Python.

## Claims this deck deliberately does not make

- The ledger is **tamper-evident, not tamper-proof**. Anyone holding the signing key can
  rewrite history and re-sign it.
- The audit ceiling is **not our theorem**. It follows from the hypothesis test in Steinke,
  Nasr & Jagielski (NeurIPS 2023 §7), with the general sample-limit point going back to
  Kasiviswanathan & Smith (2014). Ours is the empirical demonstration in the DP
  synthetic-tabular setting. Slide 6's notes say this out loud.
- No claim of immunity to floating-point side channels.
- Slide 8 lists what was **not** built — diffusion, shadow-model MIA, multi-table, Celery,
  Redis, MinIO, DuckDB, Postgres — on screen rather than in an appendix.
